# 云数据库文档（uniCloud MongoDB）

## 1. 文档说明
- 数据库位置：`/Users/zengzeng/Desktop/HBuilderProjects/salon-booking-app/uniCloud-aliyun/database`
- 本项目采用“业务主表 + 事件日志 + 审计日志”模型。
- 关键主线：`users -> orders -> order_events/order_items -> reviews/aftersales/notifications`

## 2. 集合清单
- 用户与认证：`users`, `auth_tokens`, `sms_codes`
- 门店与服务：`stores`, `services`
- 排班与时段：`barber_schedules`, `time_slots`
- 订单域：`orders`, `order_items`, `order_events`
- 评价与售后：`reviews`, `aftersales`
- 通知与审计：`notifications`, `audit_logs`

## 3. 核心数据模型

### 3.1 `users`
- 用途：系统用户（用户/理发师/管理员）
- 必填：`username`, `passwordHash`, `role`
- 关键字段：
  - `role`：角色标识
  - `storeId`：管理员/理发师所属门店
  - `pendingRole`, `approvalStatus`：理发师申请审核态
  - `serviceIds[]`：理发师可服务项目绑定
  - `phone`, `updatedAt`

### 3.2 `stores`
- 用途：门店资料
- 必填：`name`, `address`
- 关键字段：
  - `tags[]`、`businessHours`、`bookingRules`
  - `location{lat,lng}`
  - `rating{overall,service,environment,count}`
  - `barberServiceAssignmentEnabled`, `updatedAt`

### 3.3 `services`
- 用途：门店服务项
- 必填：`storeId`, `name`, `price`
- 关键字段：`duration`, `description`, `updatedAt`

### 3.4 `barber_schedules`
- 用途：理发师每日排班
- 必填：`storeId`, `barberId`, `date`, `workStart`, `workEnd`
- 关键字段：`breaks[]`

### 3.5 `time_slots`
- 用途：预约时段库存
- 必填：`storeId`, `barberId`, `date`, `startTime`, `endTime`, `status`
- 关键字段：
  - `status`：`AVAILABLE/BOOKED`
  - `orderId`：时段被占用时关联订单

### 3.6 `orders`
- 用途：订单主表（状态机核心）
- 必填：`orderNo`, `userId`, `storeId`, `barberId`, `serviceId`, `date`, `startTime`, `endTime`, `status`, `verifyCode`
- 关键字段：
  - 快照：`storeName`, `barberName`, `serviceName`, `price`
  - 状态：`BOOKED/ARRIVED/IN_SERVICE/FINISHED/CANCELLED/NO_SHOW`
  - 时间点：`arrivedAt`, `inServiceAt`, `finishedAt`, `noShowAt`
  - 其他：`verifiedBy`, `cancelReason`, `rescheduleFrom`, `autoCancelledAt`
  - 逻辑删除：`deletedByUser`, `deletedByUserAt`, `deletedByStore`, `deletedByStoreAt`

### 3.7 `order_items`
- 用途：订单明细项
- 必填：`orderId`, `serviceId`, `name`, `price`, `qty`

### 3.8 `order_events`
- 用途：订单状态变更日志
- 必填：`orderId`, `fromStatus`, `toStatus`, `opUserId`, `ts`
- 作用：用于追溯状态流转与操作审计

### 3.9 `reviews`
- 用途：订单评价
- 必填：`orderId`, `userId`, `storeId`, `barberId`, `rating`
- 关键字段：
  - `rating{overall,service,environment,barber}`
  - `content`, `images[]`, `reply`

### 3.10 `aftersales`
- 用途：售后工单
- 必填：`orderId`, `userId`, `storeId`, `type`, `status`
- 关键字段：`content`, `reply`, `status(OPEN/PROCESSING/RESOLVED/REJECTED)`

### 3.11 `notifications`
- 用途：站内消息
- 必填：`userId`, `type`, `title`, `content`
- 关键字段：
  - `type`：`booking_success/reschedule/cancel/no_show/arrival_reminder/service_start/service_finish`
  - `isRead`, `isDeleted`, `relatedId`, `relatedType`

### 3.12 `audit_logs`
- 用途：审计日志
- 必填：`actorId`, `role`, `action`, `time`, `result`
- 关键字段：`orderId`, `requestId`, `message`

## 4. 关键关系与约束

### 4.1 关系（逻辑外键）
- `orders.userId -> users._id`
- `orders.storeId -> stores._id`
- `orders.barberId -> users._id`
- `orders.serviceId -> services._id`
- `order_items.orderId -> orders._id`
- `order_events.orderId -> orders._id`
- `reviews.orderId -> orders._id`
- `aftersales.orderId -> orders._id`
- `notifications.userId -> users._id`

### 4.2 状态机约束（订单）
- 标准流转：`BOOKED -> ARRIVED -> IN_SERVICE -> FINISHED`
- 异常流转：`BOOKED -> CANCELLED`，`BOOKED -> NO_SHOW`
- 当前实现：`orders-start-service` 仅允许 `ARRIVED -> IN_SERVICE`

### 4.3 等位与等待时长
- 数据来源：订单状态 + 时间段 + 理发师维度
- 输出字段：`queueAheadCount`, `queueWaitMin`
- 使用场景：门店端待服务列表、用户订单列表与订单详情

## 5. 已落地索引（12个）与用途
以下索引以 `uniCloud-aliyun/database/*.index.json` 为准（可通过 HBuilderX/uniCloud 同步到云端）：

1. `orders.idx_orders_user_updated`：`userId(升序) + updatedAt(降序)`  
用途：加速“我的订单”列表查询与分页。

2. `orders.idx_orders_store_date_updated`：`storeId(升序) + date(升序) + updatedAt(降序)`  
用途：加速门店按日期查看订单、增量同步。

3. `orders.idx_orders_barber_date_status`：`barberId(升序) + date(升序) + status(升序)`  
用途：加速理发师维度订单查询与等位队列计算。

4. `orders.idx_orders_verify_code`：`verifyCode(升序)`  
用途：加速到店核验码匹配（`orders-verify`）。

5. `order_events.idx_order_events_order_ts`：`orderId(升序) + ts(降序)`  
用途：加速订单日志按时间倒序展示。

6. `reviews.idx_reviews_store_created`：`storeId(升序) + createdAt(降序)`  
用途：加速门店评价列表与最新评价查询。

7. `notifications.idx_noti_user_read_created`：`userId(升序) + isRead(升序) + createdAt(降序)`  
用途：加速用户通知列表、未读过滤、时间倒序。

8. `aftersales.idx_aftersales_store_status_updated`：`storeId(升序) + status(升序) + updatedAt(降序)`  
用途：加速门店售后工单按状态筛选与处理顺序展示。

9. `time_slots.idx_slots_barber_date_start`：`barberId(升序) + date(升序) + startTime(升序)`  
用途：加速可预约时段查询与时间轴排序。

10. `barber_schedules.idx_sched_barber_date`：`barberId(升序) + date(升序)`  
用途：加速理发师排班查询与编辑回显。

11. `services.idx_services_store`：`storeId(升序)`  
用途：加速门店服务列表加载。

12. `users.idx_users_username`（唯一）：`username(升序)`  
用途：保证用户名全局唯一并加速登录/注册重名校验。

对应索引配置文件：
- `orders.index.json`（4条）
- `order_events.index.json`

- `aftersales.index.json`
- `time_slots.index.json`
- `barber_schedules.index.json`
- `services.index.json`

## 6. 文档维护规范
1. 新增字段时，同步更新对应 `*.schema.json` 与本文件。
2. 新增状态值时，必须同步更新：
   - schema 字段说明
   - 云函数状态校验逻辑
   - 接口文档与测试结论
3. 版本发布前执行一次 schema 与云函数对照检查，避免“文档与实现不一致”。
