美发预约系统 数据库复现教程（检查人执行版）

适用场景
- 在新的 uniCloud 环境中，复现本项目数据库结构、索引和初始化数据。
- 本教程按“先结构索引，后数据”的顺序执行，避免导入失败。

一、交付包应包含的内容
1) 项目目录：uniCloud-aliyun/database
2) 所有表结构文件：*.schema.json
3) 云端导出的数据文件夹（云数据库json文件夹）

说明
- schema 文件负责“建表 + 建索引”。
- 云数据库json文件夹负责“导入数据”。
- 仅导入数据 JSON 不会自动创建索引。

二、检查人环境操作步骤
步骤 1：打开项目并绑定云空间
1. 用 HBuilderX 打开项目根目录。
2. 确认当前项目已绑定到检查人自己的 uniCloud 服务空间。

步骤 2：上传数据库结构与索引
1. 在左侧找到：uniCloud-aliyun/database
2. 右键 database 目录。
3. 点击“上传所有 DB Schema 及扩展校验函数”（不同版本菜单文案可能略有差异）。
4. 等待上传完成。

步骤 3：导入初始化数据
1. 打开云数据库控制台，按表进入“数据”页。
2. 使用导入功能，逐表导入云数据库json文件夹中的对应数据文件。
3. 导入后刷新数据表列表。

步骤 4：核对索引是否生效
1. 进入每张核心表的“索引”页。
2. 至少核对以下表：orders / users / time_slots / reviews / order_events / notifications。
3. 如果索引缺失，优先检查对应 schema 文件是否含 indexes 配置，再重新上传 schema。

三、推荐导入顺序（避免关联数据报错）
1) stores
2) users
3) services
4) barber_schedules
5) time_slots
6) orders
7) order_items
8) order_events
9) reviews
10) notifications
11) aftersales
12) audit_logs
13) auth_tokens
14) sms_codes

四、常见问题与处理
问题 1：导入数据成功，但查询很慢
- 原因：只导了数据，没有上传 schema，索引未创建。
- 处理：重新执行“上传所有 DB Schema...”，然后刷新索引页面。

问题 2：索引名和文档不完全一致
- 原因：历史版本中可能有“手工建索引”和“schema索引”并存。
- 处理：以当前项目的 schema 文件为准，统一重建。

问题 3：出现唯一索引冲突
- 原因：已有同字段重复数据（如 username / verifyCode）。
- 处理：清理冲突记录后重新导入，或在空环境先导 schema 再导数据。

五、复现完成判定标准
1) 所有核心表存在，且可正常读写。
2) 核心索引存在（见《数据库交付与索引核对清单.txt》）。
3) 前端能完成最小链路：登录 -> 下单 -> 到店核验 -> 开始服务 -> 完成服务。

六、简版口令
1) 先上传 schema（建表+索引）
2) 再导 init 数据（灌数据）
3) 最后看索引页确认
