理发预约系统 数据库复现教程

适用场景
- 在新的 uniCloud 环境中，复现本项目数据库结构、索引和初始化数据。
- 本教程按“先结构、再索引配置、后数据”的顺序执行，避免导入失败。

一、交付包应包含的内容
1) 项目目录：uniCloud-aliyun/database
2) 所有表结构文件：*.schema.json
3) 所有索引配置文件：*.index.json
4) 初始化脚本与脱敏示例数据：seed-*.jql、demo-data/*.example.json

说明
- schema 文件负责“建表 + 字段校验”。
- index.json 文件负责“索引配置”。
- seed-*.jql 与 demo-data 仅用于演示初始化，不包含真实用户数据、验证码或 token。
- 仅导入演示数据不会自动创建索引。

二、环境操作步骤
步骤 1：打开项目并绑定云空间
1. 用 HBuilderX 打开项目根目录。
2. 确认当前项目已绑定到目标 uniCloud 服务空间。

步骤 2：上传数据库结构
1. 在左侧找到：uniCloud-aliyun/database
2. 右键 database 目录。
3. 点击“上传所有 DB Schema 及扩展校验函数”（不同版本菜单文案可能略有差异）。
4. 等待上传完成。

步骤 3：同步索引配置
1. 确认 `uniCloud-aliyun/database/*.index.json` 文件已存在。
2. 在 HBuilderX/uniCloud 数据库面板执行“同步索引配置”（不同版本文案可能是“上传 DB 索引配置”）。
3. 等待同步完成并刷新控制台索引页。

步骤 4：导入初始化数据
1. 优先使用 `uniCloud-aliyun/database/seed-*.jql` 或 `seed-data` 云函数初始化演示数据。
2. 如需手动导入，可参考 `demo-data/*.example.json` 的脱敏字段结构自行构造数据。
3. 导入后刷新数据表列表。

步骤 5：核对索引是否生效
1. 进入每张核心表的“索引”页。
2. 至少核对以下表：orders / users / time_slots / reviews / order_events / notifications。
3. 如果索引缺失，优先检查对应 `.index.json` 是否存在并重新同步索引配置。

三、推荐导入顺序（避免关联数据报错）
1) stores
2) users
3) services
4) barber_schedules
5) time_slots
6) orders
7) order_items
8) order_events
9) reviews
10) notifications
11) aftersales

说明：`auth_tokens`、`sms_codes`、`audit_logs` 属于运行时数据，不建议作为公开演示数据导入。

四、常见问题与处理
问题 1：导入数据成功，但查询很慢
- 原因：只导了数据，未同步索引配置。
- 处理：补执行“同步索引配置”，然后刷新索引页面。

问题 2：索引名和文档不完全一致
- 原因：历史版本中可能有“手工建索引”和“index.json配置索引”并存。
- 处理：以当前项目的 `*.index.json` 为准，统一重建。

问题 3：出现唯一索引冲突
- 原因：已有唯一键重复数据（如 username，或 time_slots 中 barberId+date+startTime 重复）。
- 处理：清理冲突记录后重新导入，或在空环境先导 schema 再导数据。

五、复现完成判定标准
1) 所有核心表存在，且可正常读写。
2) 核心索引存在（见《数据库交付与索引核对清单.txt》）。
3) 前端能完成最小链路：登录 -> 下单 -> 到店核验 -> 开始服务 -> 完成服务。

六、快速流程
1) 先上传 schema（建表）
2) 再同步 index.json（建索引）
3) 最后执行 seed 脚本或按 demo-data 构造脱敏演示数据
3) 再导 init 数据（灌数据）
4) 最后看索引页确认
