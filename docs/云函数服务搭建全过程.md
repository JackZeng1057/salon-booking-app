## 1. 项目总体架构

### 1.1 系统架构图（文字版）

```
┌──────────────────────────────────────────────────────────────┐
│                        前端（uni-app）                         │
│   pages/  →  api/*.js  →  callCloud()  →  uniCloud SDK       │
└──────────────────────────┬───────────────────────────────────┘
                           │ HTTPS
┌──────────────────────────▼───────────────────────────────────┐
│                    uniCloud 云服务（阿里云）                     │
│                                                              │
│  ┌─────────────────────────────────────────────────────────┐ │
│  │           cloudfunctions/（49个云函数）                    │ │
│  │  ┌─────────────────────┐  ┌──────────────────────────┐  │ │
│  │  │  common/sb-common   │  │  各业务云函数 index.js     │  │ │
│  │  │  (12个功能子模块)    │←─│  require('sb-common')     │  │ │
│  │  └─────────────────────┘  └──────────────────────────┘  │ │
│  └─────────────────────────────────────────────────────────┘ │
│                           │                                  │
│  ┌────────────────────────▼────────────────────────────────┐ │
│  │              database/（14张集合 + 13个索引）              │ │
│  │  users / stores / services / orders / time_slots / ...   │ │
│  └─────────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────────┘
```

### 1.2 调用链路

```
页面层 (pages/*.vue)
  → 业务 API 模块 (api/auth.js, api/order.js, api/store.js …)
    → 统一客户端 callCloud(functionName, payload)  [api/client.js]
      → uniCloud.callFunction()                    [uniCloud SDK]
        → 云函数 exports.main()                     [cloudfunctions/*/index.js]
          → sb-common 公共能力                       [common/sb-common/]
            → 云数据库操作                            [database/]
```

### 1.3 三类角色

| 角色 | 标识 | 核心业务 |
|------|------|----------|
| 普通用户 (user) | `role: 'user'` | 浏览门店、预约下单、评价、售后 |
| 理发师 (barber) | `role: 'barber'` | 查看工单、开始/完成服务、设排班 |

## 2. 开发环境搭建

### 2.1 工具准备

| 工具 | 版本要求 | 用途 |

| HBuilderX | 3.x+ | uni-app 项目开发与云函数管理 |

### 2.2 项目初始化

1. **创建项目**：在 HBuilderX 中选择"新建 → uni-app 项目"，勾选"启用 uniCloud"
2. **绑定云空间**：项目右键 → "关联云服务空间" → 选择已创建的阿里云服务空间
3. **确认目录结构**：确保生成 `uniCloud-aliyun/cloudfunctions/` 和 `uniCloud-aliyun/database/` 目录

### 2.3 项目关键配置

**manifest.json** 核心信息：
```json
{
    "name": "剪约",
    "appid": "__UNI__PLACEHOLDER",
    "versionName": "1.0.0"
}
```
其中 `__UNI__PLACEHOLDER` 是公开仓库占位符，App 云打包、真机调试或正式发布前需要在 HBuilderX 中替换为自己的 DCloud AppID。

**pages.json** 配置了前端页面路由（首页、登录、门店、订单、个人中心等模块）。

### 3.2 搭建步骤

**第1步：编写 Schema 文件**

每张集合对应一个 `<集合名>.schema.json` 文件，存放在 `uniCloud-aliyun/database/` 目录下。Schema 负责：
- 定义字段类型（bsonType）
- 声明必填约束（required）
- 配置权限策略（permission）
- 内嵌索引定义（indexes）

示例 —— `users.schema.json` 核心结构：
```json
{
    "bsonType": "object",
    "required": ["username", "passwordHash", "role"],
    "permission": {
        "read": false,
        "create": false,
        "update": false,
        "delete": false
    },
    "indexes": [
        {
            "key": { "username": 1 },
            "name": "idx_users_username",
            "unique": true
        }
    ],
    "properties": {
        "username":     { "bsonType": "string", "description": "用户名" },
        "passwordHash": { "bsonType": "string", "description": "密码摘要（SHA-256）" },
        "role":         { "bsonType": "string", "description": "角色：user/barber/admin" },
        "name":         { "bsonType": "string", "description": "显示名称" },
        "storeId":      { "bsonType": "string", "description": "所属门店ID" },
        "phone":        { "bsonType": "string", "description": "手机号" },
        "serviceIds":   { "bsonType": "array",  "description": "理发师可服务项目ID列表" },
        "avatar":       { "bsonType": "string", "description": "头像" },
        "intro":        { "bsonType": "string", "description": "理发师擅长介绍" },
        "pendingRole":  { "bsonType": "string", "description": "待审核角色" },
        "approvalStatus": { "bsonType": "string", "description": "审核状态" }
    }
}
```

示例 —— `orders.schema.json` 状态机字段：
```json
{
    "status": {
        "bsonType": "string",
        "description": "订单状态：BOOKED/ARRIVED/IN_SERVICE/FINISHED/CANCELLED/NO_SHOW"
    },
    "verifyCode": { "bsonType": "string", "description": "到店核验码（6位数字）" },
    "arrivedAt":  { "bsonType": "int",    "description": "到店时间戳" },
    "inServiceAt":{ "bsonType": "int",    "description": "开始服务时间戳" },
    "finishedAt": { "bsonType": "int",    "description": "完成服务时间戳" },
    "noShowAt":   { "bsonType": "int",    "description": "爽约时间戳" },
    "deletedByUser":  { "bsonType": "bool", "description": "用户侧逻辑删除" },
    "deletedByStore": { "bsonType": "bool", "description": "门店侧逻辑删除" }
}
```

示例 —— `time_slots.schema.json` 时段库存：
```json
{
    "bsonType": "object",
    "required": ["storeId", "barberId", "date", "startTime", "endTime", "status"],
    "indexes": [
        {
            "key": { "barberId": 1, "date": 1, "startTime": 1 },
            "name": "idx_slots_barber_date_start",
            "unique": true
        }
    ],
    "properties": {
        "status":  { "bsonType": "string", "description": "AVAILABLE 或 BOOKED" },
        "orderId": { "bsonType": "string", "description": "占用该时段的订单ID" }
    }
}
```

**第2步：上传 Schema 到云端**

在 HBuilderX 中右键 `uniCloud-aliyun/database` 目录 → "上传所有 DB Schema 及扩展校验函数"

**第3步：同步索引配置**

确认所有 `*.index.json` 文件存在后，执行"同步索引配置"

### 3.3 订单状态机设计

```
            ┌──────────── CANCELLED（已取消）
            │
BOOKED ─────┤
（已预约）    │
            ├──────────── NO_SHOW（爽约）
            │
            └── ARRIVED ──── IN_SERVICE ──── FINISHED
               （已到店）     （服务中）       （已完成）
```

**状态流转规则：**
| 流转 | 操作 | 执行者 | 云函数 |
|------|------|--------|--------|
| → BOOKED | 创建预约 | 用户 | orders-create |
| BOOKED → CANCELLED | 取消订单 | 用户/管理员 | orders-cancel |
| BOOKED → ARRIVED | 到店核验 | 管理员/理发师 | orders-verify |
| BOOKED → NO_SHOW | 超时爽约 | 系统自动/管理员 | orders-no-show / autoCancel |
| ARRIVED → IN_SERVICE | 开始服务 | 理发师/管理员 | orders-start-service |
| IN_SERVICE → FINISHED | 完成服务 | 理发师/管理员 | orders-finish-service |

| # | 集合 | 索引名 | 字段 | 唯一 | 用途 |
|---|------|--------|------|------|------|
| 1 | orders | idx_orders_user_updated | userId↑, updatedAt↓ | 否 | 用户订单列表分页 |
| 2 | orders | idx_orders_store_date_updated | storeId↑, date↑, updatedAt↓ | 否 | 门店按日期查订单 |

| 5 | order_events | idx_order_events_order_ts | orderId↑, ts↓ | 否 | 订单日志倒序 |
| 6 | reviews | idx_reviews_store_created | storeId↑, createdAt↓ | 否 | 门店评价列表 |
| 7 | notifications | idx_noti_user_read_created | userId↑, isRead↑, createdAt↓ | 否 | 通知未读筛选 |
| 8 | aftersales | idx_aftersales_store_status_updated | storeId↑, status↑, updatedAt↓ | 否 | 门店售后处理 |
| 9 | aftersales | idx_aftersales_user_created | userId↑, createdAt↓ | 否 | 用户售后列表 |
| 10 | time_slots | idx_slots_barber_date_start | barberId↑, date↑, startTime↑ | **是** | 时段唯一约束 |
| 11 | barber_schedules | idx_sched_barber_date | barberId↑, date↑ | 否 | 排班查询 |
| 12 | services | idx_services_store | storeId↑ | 否 | 门店服务列表 |
| 13 | users | idx_users_username | username↑ | **是** | 用户名唯一约束 |

### 4.2 索引配置文件格式

每个索引对应一个 `<集合名>.index.json`，示例（orders.index.json）：
```json
[
  {
    "IndexName": "idx_orders_user_updated",
    "MgoKeySchema": {
      "MgoIndexKeys": [
        { "Name": "userId", "Direction": "1" },
        { "Name": "updatedAt", "Direction": "-1" }
      ],
      "MgoIsUnique": false
    }
  }
]
```

## 5. 公共模块 sb-common 搭建

### 5.1 模块定位

`sb-common` 是所有49个云函数的公共依赖，位于 `cloudfunctions/common/sb-common/`，通过 npm 本地路径引用：

```json
// 每个云函数的 package.json
{
  "dependencies": {
    "sb-common": "file:../common/sb-common"
  }
}
```

云函数中统一引入：
```javascript
const { withResponse, requireRole, ApiError, ERROR_CODES } = require('sb-common');
```

### 5.3 核心模块详细说明

#### 5.3.1 统一响应协议 (response.js + withResponse.js)

**设计目标**：所有云函数返回统一结构，前端只需判断 `code === 0` 即可。

**响应结构**：
```json
{
    "code": 0,          // 0=成功，其他=错误码
    "message": "ok",    // 成功提示或错误说明
    "data": {},         // 业务数据
    "requestId": ""     // 请求追踪ID
}
```

**withResponse 包装器**（装饰器模式）：
```javascript
// 使用方式：每个云函数只需关注业务逻辑
exports.main = withResponse(async (event, context) => {
    // 业务逻辑...
    return { ok: true }; // 自动包装为 { code: 0, data: { ok: true } }
});
// 抛出 ApiError 自动转为 { code: 400, message: '...' }
// 系统异常自动转为 { code: 500, message: 'Internal Server Error' }
```

**错误分类**：
- **ApiError（业务错误）**：如 401 未授权、409 冲突、422 业务前置条件不满足 → 如实返回
- **普通 Error（系统错误）**：数据库超时、代码BUG → 统一返回 500，不暴露内部细节

#### 5.3.2 认证与鉴权 (auth.js)

**Token 认证方案**：登录时写入 `auth_tokens` 集合 → 客户端存 token → 请求时携带 token → 后端验证

**两条验证路径**：
- 路径A：`context.auth` 平台注入（快速，无需DB查询）
- 路径B：`event.token` 手动查 auth_tokens 集合（兜底）

```javascript
// 仅需登录
const user = await requireLogin(event, context);

// 需要特定角色
const admin = await requireRole(['admin'], event, context);
// 若角色不匹配，自动抛出 403 Forbidden
```

#### 5.3.3 预约时段管理 (bookingSlots.js)

**5分钟粒度设计**：将理发师每天工作时间切分为5分钟一个slot

**时段锁定（乐观锁方案）**：
```
1. 前置冲突检查 → 查询是否有他人已占用
2. 条件更新 → WHERE status='AVAILABLE' 更新为 BOOKED
3. 后置验证 → 确认全部目标时段都被本单锁定
4. 失败回滚 → 释放已修改记录，恢复 AVAILABLE
```

**校验链（orders-create 调用顺序）**：
```
isValidBookingDate/Time
  → isAlignedToSlotStep（5分钟对齐检查）
    → buildRequiredSlotStartTimes（计算需锁定的slot列表）
      → ensureSlotTimesWithinSchedule（排班校验）
        → ensureSlotTimesWithinBusinessHours（营业时间校验）
          → ensureSlotDocsExist（按需补建slot文档）
            → lockSlotTimesForOrder（加锁）
```

#### 5.3.4 自动任务 (autoCancel.js)

三大自动能力（由 admin-dashboard 云函数触发）：

| 能力 | 说明 |
|------|------|
| 自动爽约 | 扫描超时未到店的BOOKED订单 → 标记NO_SHOW + 释放时段 + 通知三方 |
| 到店提醒 | 1小时/10分钟/5分钟三档提醒（防重复发送） |
| 评价提醒 | 服务完成30分钟后提醒用户评价（防重发、跳过已评价） |

#### 5.3.5 排队等候 (queue.js)

为 ARRIVED 状态订单计算：
- `queueAheadCount`：前方等候人数
- `queueWaitMin`：预估等待分钟数（服务中按剩余时长，其他按估算总时长）

### 6.3 核心云函数实现要点

#### orders-create（创建预约 —— 最复杂的云函数）

完整执行链路：
```
1.  鉴权 → requireRole(['user'])
2.  参数校验 → storeId/serviceId/barberId/date/startTime
3.  服务归属校验 → 查 services 集合，确认 serviceId 属于当前 storeId，并读取时长/价格
4.  理发师归属校验 → 查 users 集合，确认 barberId 属于当前 storeId 且角色为 barber
5.  理发师服务绑定校验 → isBarberAssignedToService()
6.  过去时间拦截 → 按 `+08:00` 时间戳比较预约开始时间
7.  5分钟对齐校验 → isAlignedToSlotStep()
8.  计算需锁定时段 → buildRequiredSlotStartTimes()
9.  排班区间校验 → ensureSlotTimesWithinSchedule()
10. 营业时间校验 → ensureSlotTimesWithinBusinessHours()
11. 补建时段文档 → ensureSlotDocsExist()
12. 时段锁定（乐观锁）→ lockSlotTimesForOrder()
13. 生成订单号 → `OD + Date.now() + 3位随机数`
14. 生成6位核验码
15. 写入 orders 主表
16. 写入 order_items 明细
17. 写入 order_events 事件日志
18. 写入 audit_logs 审计日志
19. 调用 `notifications-create` 云函数
20. 分别通知用户、理发师、门店管理员
21. 返回完整订单信息
```

#### admin-dashboard（管理看板 —— 聚合统计+自动任务入口）

```
1. 鉴权 → requireRole(['admin'])
2. 先执行门店范围自动爽约检测 → autoCancelOverdueBookedOrders()
3. 按单日或近7天聚合看板数据：
  - counters：订单总数、到店数、完成数、取消数、爽约数
  - rates：完成率、取消率、爽约率
  - barberStats：理发师维度统计
  - orderTrend：订单趋势
  - reviewTrend：评价均分趋势
4. 返回 `date / mode / range / counters / rates / barberStats / orderTrend / reviewTrend`
```

### 7.1 统一客户端 (api/client.js)

职责：Token注入 + 错误翻译 + requestId追踪

```javascript
// 核心调用函数
export async function callCloud(name, data = {}, options = {}) {
  const payload = { ...data };
  if (authStore.state.token) {
    payload.token = authStore.state.token;
  }

  const res = await uniCloud.callFunction({
    name,
    data: payload,
    timeout: Number(options.timeout || 15000)
  });
  const result = res.result;

  if (result.code !== 0) {
    // 翻译英文错误为中文 → 抛出
  }
  return result.data; // 只返回业务数据
}
```

**错误翻译三级降级**：
1. **精确映射**（~60条）：如 `'username already exists'` → `'用户名已被占用'`
2. **正则模式**：捕获网络错误、凭证错误等通用模式
3. **HTTP状态码兜底**：401→"请先登录"、403→"无权限"、5xx→"服务器错误"

### 10.2 架构设计亮点

| 设计要点 | 实现方式 | 设计价值 |
|----------|---------|----------|
| **统一响应协议** | response.js + withResponse.js 装饰器模式 | 前后端统一约定，消除样板代码 |
| **错误分类处理** | ApiError（业务）vs Error（系统）双路径 | 业务异常如实返回、系统异常保护内部细节 |
| **自定义Token认证** | auth_tokens集合 + requireLogin/requireRole | 无依赖第三方，实现灵活可控 |
| **时段乐观锁** | 前置检查→条件更新→后置验证→失败回滚 | 在无事务的NoSQL中实现并发安全 |
| **5分钟时段粒度** | time_slots集合 + 按需创建 | 精度与性能的平衡折中 |
| **订单状态机** | 6种状态 + 严格流转规则 + 事件日志 | 保证业务正确性，支持溯源审计 |
| **通知体系** | cloudFunction 内部调用 + 幂等写入 | 业务操作自动触发通知，无遗漏 |
| **审计日志** | 失败静默写入，不阻断主流程 | 核心可用性 > 审计完整性 |
| **中国时区统一** | chinaTime.js 手工+8h偏移 | 避免服务端UTC导致日期错误 |
| **理发师服务绑定** | 显式绑定 + 旧配对逻辑双策略兼容 | 平滑过渡，新旧数据均可运行 |
| **排队等候计算** | 按理发师+日期分组，服务中按剩余时长 | 用户体验提升，实时化信息 |
| **前端错误翻译** | 精确映射 + 正则 + 状态码三级降级 | 中文友好提示，覆盖所有异常场景 |
