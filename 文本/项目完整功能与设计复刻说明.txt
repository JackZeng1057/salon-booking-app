====================================
1. 项目定位与技术栈
====================================
- 项目定位：多角色美发预约系统（用户端 + 理发师端 + 店家管理端）。
- 前端框架：uni-app（Vue）
- 后端：uniCloud（阿里云）+ 云函数
- 数据：uniCloud Mongo风格集合
- 关键模块：
  - 认证与角色路由
  - 门店检索/详情/预约
  - 订单全流程（创建、改期、取消、核验、开始服务、完成服务、爽约）
  - 评价/售后
  - 通知中心与本地系统推送
  - AI服务顾问（图文输入，多会话）


====================================
2. 角色与权限模型
====================================
角色枚举：user / barber / admin

user（普通用户）
- 可注册登录、搜索门店、下单、改期、取消、查看订单、提交评价、提交售后、查看通知、账号设置。

barber（理发师）
- 先以user身份注册并提交理发师申请，审批通过后角色变更为barber。
- 可设置排班、查看分配订单、开始服务、完成服务、看通知、账号设置。

admin（店家）
- 注册时创建并绑定门店。
- 可看门店订单、核验到店、开始/完成服务、取消/爽约、售后处理、门店资料维护、审核理发师申请、配置理发师可做服务、查看运营看板。

9. 核心业务状态机与规则
====================================
订单状态：BOOKED -> ARRIVED -> IN_SERVICE -> FINISHED
分支状态：CANCELLED / NO_SHOW

关键时窗规则（源码）：
- 预约关闭窗口：目标时段开始前5分钟停止预约（orders-create）
- 改期窗口：原预约开始前5分钟截止（orders-reschedule）
- 取消窗口：开始后5分钟内仍可取消（orders-cancel）
- 爽约阈值：开始后20分钟仍未到店可标记NO_SHOW（orders-no-show/autoCancel）

时段模型：
- 底层粒度5分钟（SLOT_STEP_MIN=5）
- 预约窗口长度 = 服务时长 + 5分钟缓冲（REST_GAP_MIN=5）
- 排班中午/傍晚休息段不可作为起始窗口（12:00-13:00, 18:00-19:00）

10. 数据库结构（14集合）
====================================
- users：账号（username, passwordHash, role, storeId, phone, avatar, pendingRole, approvalStatus）
- auth_tokens：token会话（token唯一，expiresAt）
- stores：门店信息（基础信息、相册、标签、营业时间、预约规则、评分）
- services：门店服务（name/price/duration）
- barber_schedules：理发师排班（date/workStart/workEnd）
- time_slots：5分钟时段（AVAILABLE/BOOKED + orderId）
- orders：订单主表（快照字段+状态+核验码+时间戳）
- order_items：订单明细项
- order_events：状态流转日志
- reviews：评价（多维评分、图片、商家回复）
- aftersales：售后工单
- notifications：站内通知（isRead/isDeleted软删）
- sms_codes：短信验证码（5分钟过期，used标记）
- audit_logs：审计日志

12. 缓存与性能策略
====================================
前端缓存（utils/cache + 各API模块）
- stores列表/详情/服务/理发师：按query或id缓存
- orders列表/详情/明细/日志/评价：按key缓存并设TTL
- 状态变更后统一清理订单相关缓存，避免陈旧数据

增量同步
- orders-mine / orders-store-list / orders-barber-list 支持lastSyncAt增量拉取

云端自动任务（懒触发）
- 打开订单/通知/看板时触发autoCancelOverdueBookedOrders，自动将超时BOOKED改为NO_SHOW并触发通知


====================================
13. 通知系统（站内 + 系统推送）
====================================
站内通知类型
- booking_success / reschedule / cancel / no_show / arrival_reminder / service_start / service_finish

通知中心能力
- 分页、未读筛选、全部已读、单条删除（软删）、详情页

系统推送（utils/system-notify）
- 仅APP-PLUS启用
- 轮询间隔：30秒（App.vue）
- 冷却：45秒，防重复触发
